# AI-origin detection: primary product architecture

## Primary user question

> Was this text, image, audio, video, document or software output generated by AI?

TraceProof should **investigate** this question and provide defensible evidence. It cannot currently settle it for arbitrary files. Video overlap graphs, SHA-256 hashes and proof bundles support this investigation, but **do not identify AI-generation on their own**.

## Three evidence tiers

1. **Cryptographically verifiable provenance / vendor-specific watermark:** Check the current asset against signed C2PA actions with explicit issuer trust policy, or opt-in provider watermark verification. Identifying a supported provenance signal is narrower than proving the work was fully AI-generated or establishing a human creator's identity.
2. **Statistical detector findings:** Run appropriate open/locally deployed models with published training exclusions, hold-out tests, false-positive rates and calibration. Detector scores without validated operating thresholds are *not probabilities that the file is AI-generated*.
3. **Context and metadata:** Editing histories, software tags, traces, and user-provided documents may direct further investigation but are easy to copy or spoof.

No amount of missing evidence licenses the conclusion `human_generated`. AI involvement may be partial, and attribution to a particular vendor/model requires specific validated signals. An unrecognized generator is not necessarily a human.

## Status vocabulary

- `ai_provenance_credential`: an AI creation/composite declaration was found in the active C2PA manifest during an opt-in file inspection that reported no validation problems and contained signature information. **Signer identity and trust policy are not independently established by this adapter.**
- `unverified_ai_declaration`: imported JSON or an unsigned claim indicates AI involvement, but it is not validated or attached to the submitted asset by this inspection.
- `invalid_credential`: the external C2PA validator reported problems; no positive finding is accepted.
- `undetermined`: no usable AI creation declaration was found; not a human-origin verdict.
- `inspection_not_run`, `inspection_unavailable` and `inspection_failed`: distinguish absent consent, absent tooling and an unsuccessful inspection.

No numeric probability is output at this stage.

## Current development command

Run from source (this feature is not part of the released v0.14.0 Windows executable):

```sh
python -m traceproof ai-check path/to/sample.png
# Default: no external process and no network requests; returns inspection_not_run

python -m traceproof ai-check path/to/sample.png --c2pa-report previously-exported-report.json
# Imported JSON can be fabricated or belong to another file: unverified.

python -m traceproof ai-check path/to/sample.png --allow-external-provenance
# Requires independently installed c2patool; it may retrieve remote C2PA manifests.
```

**Privacy:** Do not opt in to external provenance retrieval for confidential media without reading the c2patool documentation and understanding which remote manifest endpoints may be contacted. Media is not uploaded to a TraceProof-hosted service. A C2PA reader can still fetch remote metadata associated with the media.

**Trust:** A signed C2PA manifest is different from a trusted signer, a real-world identity claim, a model-generated label, or the factual truth of depicted content. A future trusted-issuer policy must verify roots, revocation and the claimed tool identity. This first adapter does not do that. Imported reports are deliberately treated as unverified.

## Development sequence

1. Independently validate C2PA trust chains and add fixture tests for signed, unsigned, invalid, stripped and remote-manifest assets.
2. Add explicit opt-in watermark/provider adapters and clear disclosures about files sent outside the device.
3. Train/evaluate licensed image detectors with cross-model and cross-domain holdout sets, then extend to audio, sampled video, text and structured document/code modalities as evidence warrants.
4. Aggregate **evidence**, not arbitrary averaged scores. The user should see why each signal does/doesn't apply and can always receive “insufficient evidence.”
5. Build a unified, fully localized upload-first UI and compare all detectors against independent benchmarks before making performance claims.
